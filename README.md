# mercury — liquid portfolio

Портфолио, где весь экран — живая ртуть (raymarching-шейдер на WebGL). Капли преломляют гигантскую типографику,
тянутся за курсором и разлетаются от клика. Разделы переключаются «плавлением» постера.
Внизу справа живёт маскот **Капля** — он собирает бриф и кидает заявку тебе в Telegram.

## Запуск
```bash
npm install
npm run dev       # http://localhost:5173
npm run check     # показать все незаполненные заглушки
npm run build     # готовый сайт в /dist
```

## 🟡 Чек-лист перед публикацией
Всё, что надо заменить, помечено в коде словом **ЗАГЛУШКА** (`npm run check` выведет список).
- [ ] `src/config.js → site.url` — домен; тот же домен в `index.html` (canonical, og:url, og:image)
- [ ] `profile` — Telegram, почта (лучше на домене), GitHub, статус, фото, **честные** цифры
- [ ] `services` / `pricing` / `process` — свои цены и сроки
- [ ] `projects` — три демо-кейса (`isDemo: true`) замени на реальные, пустые слоты заполни
- [ ] `reviews` — реальные отзывы (можно скрины из Telegram — нужна только цитата, имя и компания)
- [ ] `mascot.faq` — ответы на частые вопросы
- [ ] подключи Telegram-бота (ниже) и проверь, что заявка доходит
- [ ] `site.showDemoBadges: false`, когда демо-кейсов не останется
- [ ] `public/og.jpg` — превью ссылки (сейчас — скрин главного экрана, можно оставить)

## Проекты
`src/config.js → projects`. Поля: `type, title, year, desc, task, solution, result, metrics, tags, link, image | video, slug`.
- `title: null` — пустой слот «Здесь может быть твой проект».
- `demo: 'site' | 'bot' | 'flow'` — вместо картинки показывается живое интерактивное демо из `src/demos/`.
  Для своего проекта лучше `video: 'media/x.mp4'` (запись экрана бота / воркфлоу — продаёт сильнее всего).
- У каждого кейса своя ссылка: `сайт/#works/barber-bot` — можно кидать клиентам.

## Маскот и Telegram-бот
1. В Telegram открой **@BotFather** → `/newbot` → получи токен.
2. `cp .env.example .env` и впиши `TELEGRAM_BOT_TOKEN`.
3. Напиши своему боту любое сообщение, затем `npm run tg:chat-id` — впиши полученный `TELEGRAM_CHAT_ID` в `.env`.
4. `npm run dev` → пройди бриф у Капли → заявка придёт тебе в Telegram (в dev `/api/lead` работает локально).

**Деплой на Vercel** (рекомендую): импортируй репозиторий, в Settings → Environment Variables добавь те же две переменные.
Функция `api/lead.js` подхватится сама. Есть анти-спам: скрытое поле-ловушка и лимит 5 заявок / 10 минут с IP.

**Другие варианты:** `server/cloudflare-worker.js` (Cloudflare Workers) или вебхук n8n —
просто укажи его URL в `mascot.endpoint`. Тело запроса — JSON `{ name, contact, type, ref, task, budget, deadline, page }`.

Пока бот не подключён, Капля работает в **демо-режиме**: проходит весь бриф и показывает, как заявка будет выглядеть в Telegram.

## Что ещё внутри
- Без WebGL / на слабых устройствах — статичный режим с CSS-каплями вместо шейдера.
- Ссылки на разделы (`#works`, `#contact`), кнопка «назад» закрывает кейс.
- Окна держат фокус, Esc закрывает, `prefers-reduced-motion` уважается.
- `site.customCursor: false` — вернуть обычный курсор.

## Демо для строителей «СтройДом» (`demo.html`)
Живая система продаж для строительной компании — 4 вкладки, связанные между собой:
**Калькулятор** дома (цена за минуту → заявка) · **Бот** (расчёт, запись на выезд инженера, «моя стройка») ·
**Моя стройка** (фотоотчёты по этапам, оплата по актам) · **Панель** руководителя (заявки со всех площадок,
напоминание «менеджер не ответил 15 мин», отчёты прорабов). Заявка из калькулятора или бота сразу появляется
в «Панели» и «прилетает в Telegram». Данные из форм никуда не отправляются.

- В портфолио — кейс `#works/stroydom` (в карточке крутится мини-калькулятор), кнопка «Демо на весь экран».
- Отдельная страница для лички клиенту: `https://твой-домен/demo.html`
- **Под конкретного клиента — без пересборки**, параметрами ссылки:

  `demo.html?name=СтройМакс&color=0a7d4f&m2=42000&city=Казань&manager=Ирина&foreman=Пётр&phone=%2B7%20900%20123-45-67`

  | параметр | что меняет |
  |---|---|
  | `name` | название компании (и буквы в логотипе) |
  | `color` | фирменный цвет, hex без `#` |
  | `m2` | цена м² «под ключ» из газобетона (остальное считается от неё) |
  | `city` | регион работ |
  | `manager`, `foreman` | имя инженера/менеджера и прораба |
  | `phone` | телефон в шапке (`+` пиши как `%2B`) |

  Если задан `name` — сверху страницы будет «Демо для СтройМакс».
- Коэффициенты материалов/отделки и сценарий бота — в `src/demos/BuildDemo.jsx`, умолчания — в `src/demos/brand.js`.

## Производительность
- **Тумблер «3D» в шапке.** Выключает WebGL-ртуть и включает лёгкий режим: постер главы на обычном canvas и три
  хромовые капли на CSS (перетекают на новое место при смене главы, большая тянется к курсору, клик — брызги; только
  `transform`/`opacity`). Выбор запоминается (`localStorage['vg-3d']`). Без WebGL или при «экономии трафика» лёгкий режим
  включается сам. Если качество уже на минимуме, а кадры всё равно дольше 30 мс, сайт один раз предложит «Лёгкий режим».
  Для проверки: `?static` — принудительно лёгкий режим, `?debug` — `window.__stage` (`__stage.quality`, `__stage.onSlow()`).
- **Без three.js и React.** Шейдер крутится на чистом WebGL (`src/liquid.js`, ~11 КБ), интерфейс — на Preact
  (тот же JSX и хуки). JS на старте: ~80 КБ вместо ~790 КБ.
- **Шейдер считает только там, где есть ртуть.** Лучи, не задевающие капли (с запасом на слияние и тень), не маршатся;
  вне перехода постер читается одной выборкой. Картинка та же (проверено попиксельно), кадр дешевле на ~15–30%.
- **Губернатор качества на ровные 60 fps.** Средний кадр меряется окнами по 45 кадров: дольше ~20 мс — разрешение рендера
  снижается (сильнее, если >30 мс), стабильно быстрее ~17.6 мс — плавно растёт обратно (не выше исходного: 0.85 на десктопе,
  0.6 на телефоне). После просадки действует временный потолок, чтобы качество не «прыгало». Первые 1.5 с и начало перехода не учитываются.
- **Постеры глав готовятся заранее.** Соседние главы рисуются в простое (`requestIdleCallback`) и лежат в кеше — при листании
  нет тяжёлой отрисовки в момент перехода. Постер рисуется в разрешении рендера, а не экрана (на ~28–64% меньше пикселей),
  текстура обновляется через `texSubImage2D`. Маска перехода считается один раз на пиксель для всех трёх цветовых каналов.
- **Пауза рендера**, когда ртуть не видна: вкладка скрыта, открыт кейс, на телефоне открыт чат.
- Курсор, наклон ленты работ и глаза маскота не крутят циклы вхолостую — только пока есть движение.
- **Анимации интерфейса — на видеокарте.** Покачивание маскота, блики хромовых кнопок и пульс в демо анимируют
  `transform`/`opacity`, а не SVG‑атрибуты и фон — страница не перерисовывается каждый кадр. Мини‑демо в ленте работ
  встают на паузу, когда вне экрана или под открытым кейсом; закрытый чат и отыгравший лоадер убираются из отрисовки.
- Шрифты: только кириллица и латиница, ключевые начертания с `preload`. Тяжёлые `backdrop-filter` и `drop-shadow`
  поверх живого канваса заменены на плотный фон и градиенты.

Сводка изменений и проверок — в `RESPONSIVE_FIXES.md`, раздел «Итерации 5–7». В проект включены накопленные правки v4–v6 и финальный аудит v7.
